# Run Nova and install its browser extension

Nova runs locally on your computer. This extension build supports Google Chrome,
Microsoft Edge, and compatible Chromium browsers. It does not support Safari,
Firefox, or embedded browser previews.

## Start the project

From the Nova project folder, with Node.js 20.19 or newer:

```sh
npm ci
cp .env.example .env
# Fill the provider keys in .env before starting Nova.
npm run build
npm run dev
```

Keep this terminal running. Enter your own OpenAI and Sarvam credentials in `.env`
and restart the backend after changing them. Never put those keys in the extension
folder. On an existing checkout, keep your current `.env` instead of copying over it.

Open [Nova Settings & setup](http://127.0.0.1:5173/#setup) in the browser you intend
to use. The dashboard should say **Nova is online**.

## Download and install

1. Click **Download Nova extension** on the setup page. The
   [direct ZIP link](http://127.0.0.1:5173/downloads/nova-extension.zip) works while
   Nova is running.
2. Extract the ZIP. On Mac, double-click it. On Windows, right-click and choose
   **Extract All**. Move the extracted `nova-extension` folder to a permanent
   location, such as Documents. Keep this folder while the extension is installed.
3. In Chrome, copy `chrome://extensions` into a new tab's address bar. In Edge,
   use `edge://extensions`. Press Enter. The dashboard provides a **Copy address**
   button because browser settings addresses cannot open as ordinary webpage links.
4. Enable **Developer mode**. Click **Load unpacked** and select the extracted
   `nova-extension` folder containing `manifest.json`. Do not select the ZIP or
   its parent folder.
5. Return to Nova in the **same browser and profile**, then refresh the dashboard.
   Setup should show **Nova extension connected to this browser** and version
   **0.7.1**. You may pin Nova to the browser toolbar; this is optional.
   Versions 0.5.0 and later use Chrome’s browser-debugger permission for trusted input and
   screenshots. Accept the new permission if Chrome asks when enabling/updating Nova.
   Chrome displays a control banner while Nova is connected to a website.

The browser requires a manual install action. Downloading alone does not install
the extension. This is a local development distribution, not a browser-store listing.

Official illustrated guides:
[Chrome installation](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)
and [Edge installation](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading).

Developers can select `web/dist-extension` directly instead of downloading. The
ZIP and that directory contain the same build; both are generated by `npm run build`.

## Chat beside your website

1. Choose **Test with the demo shop**, or select **Open with Nova** on a website
   card. Nova creates a new tab in the exact window hosting the dashboard.
2. On a domain's first use, click **Enable Nova on this website** and approve the
   browser's website access request. That same tab navigates to the actual URL.
3. Click Nova's floating button. It opens a **native browser side panel** beside
   the website, with **Chat** selected. The website resizes to make room; the
   conversation does not cover it. Try “scroll down” or “zoom in” first.
4. Continue with a task such as “Find an adapter and show me its details.” Nova
   asks when a missing detail changes what it should do. Routine browsing and
   clearly requested cart changes proceed without another confirmation. Purchases,
   sending or publishing, deletion, and sensitive account changes require review.
   To speak, choose **Live talk**. On first use, Nova opens a microphone setup
   tab so Chrome can show its permission prompt. Choose **Allow**, click **Back to
   Nova**, and start voice in the panel. Chrome reuses the permission across Nova’s
   websites while it remains allowed. Returning
   to **Chat**, closing the panel, or switching away from the active website stops
   microphone capture. The conversation stays through page reloads.
5. To end, use **Dashboard → Activity → End session**. The assistant disappears,
   and the website stays open. Reloading that tab does not restart Nova.

Only Nova-launched tabs and tabs you explicitly attach using the toolbar activate
the companion. Ordinary website visits are unchanged, even after granting domain
access. One Nova website session is active at a time; launching another removes
the previous companion. Existing browser sign-in stays in that browser profile.

## Troubleshooting

| Symptom | What to do |
|---|---|
| Download says “Build required” | Run `npm run build`, then click **Check download again**. |
| Extension cannot load | Extract the ZIP and select the inner folder containing `manifest.json`. |
| Extension not detected | Use the same supported browser/profile, enable Nova on its extensions page, then refresh the dashboard. |
| Nova is offline | Keep `npm run dev` running; inspect its terminal for a startup error. Ports 5173 and 8787 must be available. |
| Side panel does not open | Update to extension 0.7.1, reload it on the extensions page, refresh the dashboard, and launch a fresh session. Use a recent Chrome/Edge version with native side panel support. |
| Floating button missing | Launch from Nova, allow the domain on the launch screen, and wait for navigation. Ordinary visits do not activate it. Check that another session has not replaced this one. |
| Controls look stale after updating | Click **Reload** on the extension card, refresh the dashboard, end old sessions, and relaunch websites. |
| Voice cannot start | Update to 0.7.1 and choose **Live talk**. Complete the microphone prompt in Nova’s setup tab. If blocked, use **Open microphone settings** there to allow/reset Nova; on Mac also enable your browser in **System Settings → Privacy & Security → Microphone**. Then retry. Chat remains available. |
| Screenshot says all_urls/activeTab is required | Update/reload 0.7.1 and accept its browser-control permission. Screenshots now use the attached tab’s browser-control connection. |
| Browser control disconnected | Click **Resume browser control** in Nova. Close DevTools or another debugger attached to that tab if Chrome refuses the connection. |
| Nova cannot confirm an action | Check the observed page state before retrying a saved change. A click alone no longer counts as completion. |
| A new domain stops the task | Enable Nova on that destination through the dashboard or explicitly attach with its toolbar icon. Domain access does not transfer everywhere. |
| Website asks for login or human verification | Complete that step yourself on the website. |

Browser internal pages, extension stores, protected surfaces, and some site
controls cannot be operated by this extension. See [capabilities](CAPABILITIES.md)
and [validation](VALIDATION.md) for tested behavior and limitations.

## Update, remove, and production bundle

To update, build/download the new ZIP and extract it. Replace the files inside
the **same installed folder**, preserving its path. Click **Reload** on Nova's
extension card, refresh the dashboard, and relaunch your sessions. The setup page
reports when the installed version differs from the available version.

To uninstall, end the current session and click **Remove** on Nova's extension
card. You can then delete the extracted folder.

To serve the built dashboard locally without the Vite development server:

```sh
npm run build
npm start
```

Use [built dashboard setup](http://127.0.0.1:8787/#setup) and its
[extension download](http://127.0.0.1:8787/downloads/nova-extension.zip). These URLs
use the same local backend. Keep port 8787 for this extension build; it is not a
hosted multi-user deployment.

Dashboard launches pair automatically. Manual pairing through the extension
toolbar uses the **Copy pairing token** button under the setup page's advanced
instructions. Treat that token as private; it is separate from provider API keys.

## Make the companion specific to a website

In **Your websites → Configure**, edit the website name, accent, companion
introduction, site instructions and suggested tasks. These appear in the panel
and guide replies; they do not limit the shared browser engine. Suggested tasks
prefill the composer so you can add details before sending. Changes update active
sessions. See [general agent architecture](GENERAL-AGENT.md).

### Follow-up cards (0.7.1)

When a task needs important details, Nova collects them in a card inside its side panel. Choose options or enter your own answer, then select **Continue**. Related questions appear together; answers already given in chat should not be requested again. **Help me choose** sends the answers entered so far with a request for guidance. You can also answer or correct a detail in the normal chat box or by voice. Submitted cards keep a collapsible record of the answers.

These cards collect task details. Consequential actions retain a separate confirmation with the actual operation. An incomplete, cancelled or outdated card cannot trigger execution; repeated submission is rejected by the backend. Nova never asks for passwords, API keys, OTPs or payment secrets through these forms.

Reload the unpacked extension after replacing its files with version 0.7.1, then reconnect or open a fresh Nova session. No new extension permissions are required for this update.
