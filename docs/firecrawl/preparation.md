## Decision for the coordinator

Under a broad rule excluding companies with AI agents that actually perform tasks, **skip Firecrawl**: public evidence clearly meets it, including browser control. Under the user's more specific rule excluding an assistant that operates the company's own dashboard, evidence remains unresolved. The public architecture distinguishes target-site browser execution from account/dashboard operation. Inspect the actual team dashboard and any assistant controls before deciding; do not quietly broaden or narrow the criterion to obtain a demo candidate.

Bounded live check: verify account/team, identify native Agent/Browser/Ask controls, and determine whether there is a conversational assistant that itself configures a bounded Playground scrape/crawl, saves/runs it, navigates Activity Logs and revises that dashboard task on request. Prefer capability inspection and read-only navigation initially; do not reveal API keys or purchase credits. If the same native assistant completes the intended end-to-end dashboard flows, mark skipped with evidence. If only the separate research/browser product is available, coordinator may record that precise distinction and approve eligibility.

No two-flow Nova scenario is selected while eligibility is unresolved. In particular, research/extraction alone would duplicate the native Agent; failed-job explanation/validation alone would duplicate Ask. Only after eligibility confirmation should two substantial supported dashboard workflows be chosen and exercised through their saved-result routes.
